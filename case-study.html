Case Study: Building HealthLens

HealthLens is a student project exploring how accessible digital content, structured resources and responsible signposting can help international students navigate wellbeing and practical support in the UK.

Portfolio summary

HealthLens is a multi-page static information platform for international students in the UK. I designed and built the site using HTML, CSS and JavaScript, with JSON-based resources, curated guide cards, global search, source quality labels, accessibility-informed templates, dark mode, print CSS and audit documentation.

The problem

International students often need to understand several unfamiliar UK systems at once: university support, healthcare, housing, money, community and urgent help. Search engines can return many results, but they do not always explain which sources are official, expert, student-facing or relevant to a specific situation.

Target users

  • International students in the UK
  • Students new to UK university systems
  • Students looking for official or expert support resources
  • Students who need plain-English summaries and next steps

Product positioning

HealthLens is an International Student Wellbeing Navigator. It is not a medical, legal, financial, immigration or emergency advice service. It organises official and expert resources into clearer pathways and adds plain-English context.

Information architecture

The site is organised into topic hubs, a resource library, health tips, global search, source policy and project documentation:

  • Home
  • Resources
  • International Essentials
  • Health & Healthcare
  • Mental Wellbeing
  • Housing & Bills
  • Money & Everyday Spending
  • Community, Activities & Sport
  • About / Source Policy
  • Search
  • Case Study

Topics are separated because healthcare and mental wellbeing are different user needs; housing and money are practical life topics; resources and guides serve different browsing behaviours; and the source policy page builds trust through transparent labelling.

Content model

  • resources.json stores official and expert links rendered as resource cards
  • articles.json stores curated health tip summaries
  • topics.json stores searchable topic page metadata
  • Source metadata records source type, authority, audience, region, risk level and last checked date

Search design

The global search builds a client-side index from topic pages, resources and health tips. Users can search by keyword, filter by content type and filter by topic.

  • No backend required — works on GitHub Pages
  • URL query parameters support direct links (e.g. search.html?q=GP)
  • Accessible result status message with role="status" and aria-live="polite"

Accessibility approach

  • Semantic HTML and logical heading hierarchy
  • Visible labels on search inputs and filters
  • Keyboard navigation and visible focus states
  • Skip link to main content
  • Descriptive link text (no “click here”)
  • aria-live status for search results
  • Dark mode contrast checks
  • Print-friendly CSS
  • Mobile responsive layout

The project is WCAG-informed, but not formally certified.

Content safety and source governance

  • Official sources are prioritised for healthcare, urgent help, university services and rules
  • Expert sources are used for housing, money and international student guidance
  • Commercial platforms are labelled clearly and are not presented as financial advice
  • “Last checked” means HealthLens checked the link and summary — not that the original source was updated
  • High-risk topic pages include limitation notes and signposting-only wording

Key design decisions

  • Wellbeing navigation, not health advice

    Reframed from a broad health support concept to an International Student Wellbeing Navigator with clear boundaries.

  • Resources and guides separated

    Official links live in the resource library; plain-English summaries live in health tips.

  • Source quality labels

    Every card shows source type, authority and last checked date for transparency.

  • Last checked dates

    Review dates show when this project checked a link — not when the original source changed.

  • Signposting-only health content

    Healthcare routes are explained without diagnosis, treatment or triage wording.

  • Static-first for GitHub Pages

    JSON data, vanilla JavaScript and relative paths keep deployment simple and maintainable.

Limitations

  • This is a student project — not a live university service
  • It is not professional advice of any kind
  • Links and summaries require periodic review
  • Automated accessibility checks cannot catch everything
  • No user testing with real international students has been completed yet

Future improvements

  • Conduct user testing with international students
  • Add more health tip articles
  • Improve search ranking and relevance
  • Add a clearer content review workflow
  • Add multilingual summaries
  • Consider a CMS or static site generator in future
  • Expand accessibility testing with screen reader checks
